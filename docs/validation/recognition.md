- Область предмета берётся из существующей разметки COCO, с фиксированным
  запасом 12% с каждой стороны. Ручного выбора области по ответам Vision нет.
- Категории, изображения, координаты и допустимые английские синонимы

- Классификация: `VNClassifyImageRequestRevision2`, три наиболее уверенных

- Совпадение: точное совпадение нормализованного английского названия с одним
  из заранее объявленных синонимов; общие категории не засчитываются.

- SHA-256 manifest: `3b8fdc3cd6961ab3bafd3e39e9ab57eb02a0f533953d9daacd67e6cb0d71d590`.
- SHA-256 исходного архива: `61e5e3028863d8ffc3b81d6a514603954889f0edd5e4b44c4ce60b2da99aeb8e`.

## Причины и границы вывода

Vision возвращает одновременно конкретные предметы и общие категории.
Например, `suitcase` находится за категориями `structure`, `wood processed`
и `material`, а `banana` — за `plate`, `tableware` и `utensil`. В полном
ответе правильное название чемодана находится на позиции 6, банана — 6,
часов — 4. Простой выбор трёх максимальных confidence не подходит для
учебного словаря без дополнительного отбора предметных названий.

Набор ограничен: некоторые снимки содержат людей, фон, части предметов
или другие вещи. COCO-категории не всегда соответствуют точному учебному
названию: например, `television` включает фотографию компьютерного монитора.
Близкие ответы `drinking glass`, `timepiece`, `stuffed animals` не были
добавлены в допустимые синонимы после получения предсказаний. Поэтому
10/30 — результат конкретного зафиксированного протокола, а не универсальная
оценка Vision и не оценка распознавания на фотографиях пользователя.

Медианное время запроса с подготовкой crop на Mac: 12.5 мс.
Это не измерение задержки камеры или скорости на iPhone.

## Предложение следующего шага

Пересмотреть распознавание до разработки основного интерфейса:

1. Сохранить Apple Vision и отдельно проверить отбор конкретных предметных
   классов вместо общих категорий. Это потребует явного перечня поддерживаемых
   предметов и проверки на новом наборе фотографий; прохождение 24/30 не обещается.
2. Использовать отдельный предметный детектор через Core ML, например YOLO,
   после выбора модели и проверки её условий использования. Для проверки YOLO
   нужен независимый набор: COCO128 состоит из обучающих снимков COCO и не
   должен служить независимой оценкой модели, уже обученной на COCO.

Ни один вариант не подключён автоматически. Текущий код и отчёт позволяют
принять решение до дальнейшей разработки.

- Swift 6: общий сервис скомпилирован и выполнен на Mac.
- iPhone 17 Pro Simulator, iOS 26.4: **6 тестов пройдены**, 0 ошибок и пропусков

- Release-сборка для `generic/platform=iOS` без подписи: **успешна**.
- В сборке есть штатное предупреждение пропуска App Intents metadata:
  приложение не использует AppIntents. Ошибок компилятора нет.
- Проверены синтаксис benchmark.sh, компиляция Python-утилиты и plist проекта.
- Физический iPhone: запуск не выполнен — Developer Mode выключен.
- Камера, перевод, офлайн-перевод, речь, SwiftData и основной продуктовый
  интерфейс не реализованы и не проверены: до них контрольная точка не пройдена.
